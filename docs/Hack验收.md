# Hack 验收

> 通用版，可以放进任何项目（建议放在 `docs/Hack验收.md`），由项目说明（CLAUDE.md 或同类文件）引用。
> 写给做开发的 AI agent，人也能读。标【项目填写】的三节（第 3、4、7 节：红线、合成环境与配方、回归关卡）
> 第一次落地时按项目填，尖括号 `<…>` 换成具体内容。

借编程竞赛（ACM）里的 hack：选手交题以后，别人拿反例来打它。写代码的 agent 专心把功能做对；换一个
**不共享实现上下文**的 agent（Hacker），以"弄坏它"为目标读改动、造对抗输入，交回能复现的反例，或者
"试了哪些、没打破"；外加一条真路径上的证据。它取代"每个改动都配一套新测试"。

为什么这样做：
- **作者有盲区**：自己想到的边界早就处理了，没想到的自己也测不到。换一个 agent 才看得见。
- **测试全绿不等于功能对**：AI 写的测试常常探的是"改了什么"（源码里有某句话、函数被调用了、拿当前输出当期望），
  不是"行为对不对"。这类测试越写越多、越跑越慢，挡不住真问题。
- **反例比断言便宜**：一条"这样调 → 得到 X，应该是 Y"，比一套测试更快写出来，也更难自欺。

## 1. 每个改动怎么走

1. **实现**：专心做对。不写新测试，也不做"先在旧代码上失败"的仪式。改完跑回归关卡（第 7 节），必须全绿；
   有现成的配方脚本（第 4 节）就先跑一遍。
2. **按风险分档**，决定派不派、派谁、给多久（拿不准就往上一档）：

   | 档 | 什么改动 | 怎么验 | 时限 |
   |---|---|---|---|
   | 不派 | 文档、注释、日志措辞、删测试、等价的搬代码、不碰挡板的工具脚本 | 作者跑关卡和相关配方，把输出写进验收行 | — |
   | 快打 | 一般的功能、页面、接口、命令行改动 | 较快的模型，只打 spec 里列的 ≤ 3 个风险点 + 一条真路径 | 约 8 分钟 |
   | 全打 | 本项目：任务 / 设置的持久化（原子写、损坏备份、撤销、退出前刷盘）、API Key 的保存与使用、对外的 AI 网络请求、挡板（`src/main/sandbox.ts`）本身 | 最强的模型，再加第 5 节对抗清单里相关的几类 | 约 15 分钟 |

   小模型（如 Haiku）只做机械的重跑，不找反例。
   **本项目例外：用户指定 Hacker 一律用 Opus 5.5，思考等级 high（第二版起从 Haiku 5.5 换成 Opus 5.5）。**
3. **派 Hacker**：另起一个后台子 agent，spec 照第 6 节写，不在 spec 里替它下结论。**思考等级显式指定 high**：
   不指定的话子 agent 会继承主会话的等级，成本和行为都不可控。
   （Claude Code 里：`Agent` 工具，`run_in_background: true`，传 `model` 和 `effort: "high"`。）
4. **别干等**：Hacker 跑的时候接着做别的（下一个问题、文档、提交信息）；互不相关的改动同时派几个 Hacker；
   慢的关卡和测量也放后台。超过时限一倍还没回报就停掉它（Claude Code 里：`TaskStop`），按已有结果决定补派还是收尾。
5. **Hacker 交回**：反例（复现命令 + 实际输出 + 期望输出 + 期望从哪来），或"试了哪些、没打破"，外加真路径证据。
   作者把每条反例**自己重跑一遍**，确认是真的再修。
6. **修完复跑：交回同一个 Hacker**（Claude Code 里：`SendMessage` 发给它）。它还记得自己的复现脚本，只复跑打出的反例
   和改到的地方，一般 2 分钟左右；新开一轮要 8 分钟以上。只有修的时候新加了大块代码才新开一轮。
   在第 7 节那几块打出的真 bug，把反例加进关卡。
7. **核对 Hacker 真的按要求跑了**：到它的记录里看一眼模型和思考等级（续用之后模型别名可能解析成别的版本）。
   看不到记录就在验收行写"未核对"。
8. **提交**：提交信息末尾写一行验收：

   ```text
   验收：<真路径证据，一句话>；Hacker：<模型 / 思考等级>；打出：<反例，已修 / 无>
   ```

   **只写真实发生的**：没派 Hacker 就写"Hacker：无"，核对不了模型就加"（未核对）"，什么都没验就写"验收：未验"。
   编一行好看的验收行比老实写"未验"糟得多：读的人会以为这个改动被打过。

**你不是作者时**（用户让你验收别人写的改动）：你本来就是"另一个人"，可以自己当 Hacker 打，也可以再派一个。
照样按分档决定花多少力气，照样交回反例和验收行；Hacker 一栏写实际是谁打的，例如"本会话（非作者）/ <模型>"。

**你自己是子 agent 时**：你派出的 Hacker 的完成通知可能送不到你这里，它的记录你也可能看不到，要主动去读它的输出；
有的环境不让子 agent 写文件，这时把报告作为文字交回。

## 2. 什么算证据

- **算**：真路径上的行为。例如：用合成数据起服务后真请求的响应、浏览器里的真页面、命令行的真输出、
  数据库 / 文件里真实写下的东西。界面改动要在真窗口里看真页面（源码副本 + 合成数据）。
- **不算**：测试全绿、源码里有某段字符串、文件存在、函数被调用了几次、拿当前实现的输出当期望。
- **期望值要有独立来源**：来自造数据时放进去的东西（放了几条、原文是什么、哪条该命中），或者需求本身
  （本项目：`docs/初版计划.md` 和设计稿），不来自被测代码自己算出来的结果。
- **说清验到了哪一层**：只在合成数据上验过的要写明。只有真实环境才能验的（真实账号、真实硬件、第三方服务），
  单独列出来交给用户确认。

## 3. 红线【项目填写】

本项目真实的危险：
- **用户的真实数据**：应用正常运行时的 userData 目录（`%APPDATA%\` 下以应用名命名的目录，内含 `tasks.json`、`settings.json`，
  后者里有加密的 API Key）。只有带挡板启动时，程序才会改用 `QINGXIN_DATA_DIR`。
- **外部系统**：AI 服务（用户自己提供的 OpenAI 兼容接口，会产生费用）；开机启动会写注册表 Run 项；系统通知。
- **含密钥的东西**：settings.json 里的 `apiKeyEnc`；用户可能在环境变量或别处放了真实 Key。
- **用户正在用的程序**：Claude 桌面版、浏览器、编辑器等，其中不少本身就是 Electron（进程名都可能叫 electron 或类似）。
- `E:\todolist\logs\` 是用户的目录，与本项目代码无关。

能原样贴进 spec 的精简版：

```text
红线（docs/Hack验收.md 第 3 节，细节去那里看）：
- 只用合成数据：任务和设置都在你自己的临时目录里造。不碰 %APPDATA% 下的任何应用数据、E:\todolist\logs\，
  不碰用户正在运行的任何程序（Claude、浏览器、编辑器、其它 Electron 应用）。
- 被测程序一律带挡板启动：环境变量 QINGXIN_SANDBOX=1、QINGXIN_DATA_DIR=<你的临时目录>\data、QINGXIN_SANDBOX_QUIET=1
  （安静模式：窗口在屏幕外、不抢焦点、不进任务栏，用户正在用这台电脑）。不要调用 bringToFront / focus 之类会激活窗口的操作。
  不要不带挡板启动（npm run dev、直接双击、直接跑 electron 都算），不要故意绕过挡板。
- AI 服务只用你自己在 127.0.0.1 上起的假服务（临时脚本，放你的临时目录）；不联网；Key 只用 sk-fake-… 这类假值。
  不改系统设置、注册表、开机启动项。
- 不改仓库里的任何文件，不往项目里装依赖，不提交。允许在项目根目录跑 npm run build（只产出 out/）。
  你的脚本、依赖（例如 playwright-core）和数据都放 %TEMP%\qingxin-hack-<随机>\，用完删；只结束自己起的进程（按 PID，不按进程名）。
- 不用 REA（mcp__rea__*）工具。
- 同一个错误试两次不过就停下来回报事实，不要改被测代码去"让它过"。
```

真实数据的规矩：
- 要在真实数据上排查，先向用户说清读什么，征得同意。只读，只输出必要的计数，不输出内容。
- 用户正在用的程序，只发只读请求、只记耗时和计数；不拿新代码去打开真实数据。
- 用户同意提取的真实样本另立规矩：放在仓库外、不看内容、只做字节级检查，用完删工作目录。

## 4. 合成环境与配方【项目填写】

**带挡板的启动方式**（程序自带，见 `docs/初版计划.md` 3.2）：`QINGXIN_SANDBOX=1` + `QINGXIN_DATA_DIR=<绝对路径>`，
自动化反复启动时再加 `QINGXIN_SANDBOX_QUIET=1`（窗口放到所有屏幕之外、`showInactive` 不抢焦点、不进任务栏、关掉 Windows
遮挡检测让它照常绘制；PrintWindow 和 CDP 截图都正常）。
挡板模式下：数据目录改到 `QINGXIN_DATA_DIR`；开机启动只写 settings 不碰注册表；AI 地址只允许本机回环；不弹系统通知。
playwright-core 的 `_electron.launch` 在 Electron 44 上会报 "Process failed to launch!"，改用
`electron.exe E:\todolist --remote-debugging-port=<端口>` 启动，再 `chromium.connectOverCDP('http://127.0.0.1:<端口>')`。
它不防故意绕过（例如直接改代码、直接调 Node 模块），要求 Hacker 不这么做。挡板本身改了，属于"全打"。

**怎么像用户一样操作它**（不写进仓库的临时脚本）：
1. 在项目根目录 `npm run build`。
2. 在 `%TEMP%\qingxin-hack-<随机>\` 里 `npm init -y && npm i playwright-core`。
3. 临时脚本里用 playwright-core 的 `_electron.launch({ executablePath: 'E:\\todolist\\node_modules\\electron\\dist\\electron.exe',
   args: ['E:\\todolist'], env: { ...process.env, QINGXIN_SANDBOX: '1', QINGXIN_DATA_DIR: '<临时目录>\\data' } })`，
   拿到窗口后像用户一样点击、输入、按键、调整窗口大小、重载，截图留证。
4. 需要 AI 时，在临时目录里起一个 Node 小服务（`127.0.0.1` 随机端口，实现 `POST /v1/chat/completions`），按需要返回
   正常 / 畸形 / 超慢 / 报错的回复；在应用的设置里把地址填成它。

**造数据**：启动前直接往 `<临时目录>\data\tasks.json` 写合成任务（格式见 `docs/初版计划.md` 3.3），同时记下"应该显示成什么"。
默认就造容易藏 bug 的形态：逾期的、跨午夜的、同一时间并列的、没日期有时间的（非法）、超长标题、emoji / 零宽字符、重复 id、坏 JSON。

**取旧版本对比**：本项目目前不是 git 仓库；需要对比时把源码复制到临时目录。

本项目：
- 启动方式：上面第 1–3 步
- 在 Linux 云容器里跑（没有 Windows 时）：`node node_modules/electron/install.js` 下载 Electron 二进制；safeStorage 需要解锁的
  keyring（容器里 `apt-get install gnome-keyring`），否则保存 Key 会被拒绝。启动（挡板安静模式）：
  `QINGXIN_SANDBOX=1 QINGXIN_DATA_DIR=<临时目录>/data QINGXIN_SANDBOX_QUIET=1 dbus-run-session -- sh -c "printf x | gnome-keyring-daemon --unlock --components=secrets >/dev/null 2>&1; exec xvfb-run -a -s '-screen 0 1600x1000x24' node_modules/electron/dist/electron . --no-sandbox --password-store=gnome-libsecret --remote-debugging-port=<端口>"`，
  再 `chromium.connectOverCDP`。用 detached 启动、按进程组结束（只杀 xvfb-run 会留下 electron）。Linux 上验不了托盘和 Windows 窗口行为。
- 造数据：直接写 `tasks.json` / `settings.json`（设置里的 Key 只能通过界面填假值，因为是加密存的）
- 配方：暂无
- 挡板下验不了、只能用户在真实环境确认的：真实 AI 服务的整理准确率和总结质量、开机自动打开、系统通知及点击跳转、
  safeStorage 在用户机器上的加密、安装包的安装 / 卸载、高 DPI 与多显示器

## 5. 对抗清单

按改动挑相关的几类给 Hacker，再加这次改动特有的。每类后面的"例"都是真实项目里 Hacker 打出来的反例，当时原有测试全绿，
用来提示该往哪个方向想。

1. **输入与路径**：`..`、绝对路径、盘符、UNC、正反斜杠混用、尾随点和空格、保留名（`CON`、`NUL`）、超长路径、
   大小写不同的同一路径、符号链接 / junction；空串、`None`、超长、通配符（`%`、`_`、`*`）没转义。
   重点是从 query、表单、配置、文件名进来的值。
   - 例：同一个目录写成正斜杠、反斜杠加末尾 `\`、全大写，被当成三个不同目录，各触发一次昂贵的操作。
2. **内容与编码**：非 UTF-8（GBK、混合编码、截断的多字节）、坏 XML / JSON / protobuf、压缩过的字段、CDATA 和
   HTML 实体、emoji、零宽字符、CRLF、文件结尾多出几个字节。
   - 例：数据库里一部分正文是压缩存的，`LIKE '%词%'` 对压缩后的字节永远不命中，某类消息 100% 搜不到；
     测试数据里一条压缩的都没有。
   - 例：去标签的正则把整段 `<![CDATA[…]]>` 当成一个标签吃掉，正文丢了，id、时间戳这些数字反而能搜到。
   - 例：结构检查要求文件在结束标记处正好结束，结尾多 1 个字节的合法 GIF / PNG 被判成"不是图"并永久放弃。
3. **数据形态**：同一实体分在多个分片 / 分区 / 文件里；不同分片里 id 重号；排序键并列；空表、缺表、缺列、旧结构；
   一条记录对应多个文件。
   - 例：多分片归并翻页时，列表推导里的生成器表达式晚绑定了分片序号，多分片的会话翻出别的消息。条数完全正确，
     只有逐页比对内容才看得出来；验证基准只有一个分片，碰不到。
4. **持久化与合并**：同一条处理两次、处理到一半中断（残留的中间文件）、导入两次、导入旧版本的数据、源数据被原地改写
   （撤回 / 编辑）、并发写。核心问题：数据会不会丢、会不会重复。
5. **缓存与失效**：源数据改了缓存是否失效；失效判据会不会被骗（大小不变、修改时间被改回、文件系统时间精度粗）；
   上限与淘汰；超上限时退回旧路径是否仍正确；多线程共享缓存时只读不改。
   - 例：缓存键用"路径 + 大小 + 修改时间"，重建后大小恰好不变、修改时间被恢复时返回旧结果；加上文件头里的修改计数才稳。
6. **状态与"一次就下定论"**：凭一次结果就写下永久状态（"已试过 / 不再重试 / 已失效"）的逻辑，是反例最密集的地方。
   问自己：这次失败会不会来自网络、代理、限流、拦截页、偶发错误，而不是对象本身？
   - 例：下载失败就把地址标成"试过、不再请求"，遇到登录页、代理拦截、偶发 404，好地址被一批永久判死。最后稳定的规则是
     "只有明确的定论（拿到完整结果，或两次独立请求都明确说不存在）才写永久状态"，其余记"下次再看"。
7. **并发与时序**：两个请求同时到；慢响应回来时用户已经离开 / 改了输入；重复点击；中途停止；进行到一半的任务残留；
   浏览器对同一主机的并发上限。
   - 例：页面状态请求很慢，用户在它回来前手动触发了一次操作并已结束，状态回来后又自动触发一次。
   - 例：沙箱 / 杀软的钩子 DLL 在多线程同时建 socket 时崩溃，而域名解析内部也会建 socket。只给 socket 创建加锁不够，
     域名解析也要进同一把锁。
8. **网络与运行环境**：代理（尤其是 fake-ip：所有域名解析成 198.18.0.0/15）、登录门户、DNS 劫持、IPv4 映射的 IPv6、
   离线、限流；缺某个外部工具（ffmpeg / node）、禁了子进程；CRLF 检出、中文和空格路径；杀软 / 沙箱环境。
   - 例：防 SSRF 的"不连内网"检查把 fake-ip 段当内网，用户机器上所有下载一个都没成功；放行这一段后，这道检查在
     fake-ip 机器上又形同虚设。两头都要写进结论。
9. **资源与残留**：数据库连接、文件句柄没关（Windows 上文件删不掉）；子进程、后台命令残留；临时文件写进仓库或
   数据目录；内存随数据量无上限增长。
   - 例：Hacker 自己留在后台的命令一直占着它的临时目录，删不掉。
10. **安全边界**：路径穿越；SSRF（重定向的每一跳、解析结果、IPv6 写法、白名单后缀没有点号边界）；`Host` 头
    （DNS 重绑定）；跨站请求；权限检查绕过；凭据被打印 / 写进日志；开放重定向。
11. **等价性**（重构 / 优化）：新旧代码在同一份数据上逐项比对：第一页、中间、最后一页、超出范围；各种排序；各种筛选
    组合；超出缓存上限时退回的旧路径。只比总数会漏掉"条数对、内容错"的 bug。

## 6. 派 Hacker 的 spec 模板

```text
<快打 / 全打>，限 <8 / 15> 分钟，到点先回报已有的。你是 Hacker：目标是弄坏下面这个改动，不是证明它对。
项目 <路径>；<怎么跑代码：解释器 / 包管理器 / 启动命令>。

改动：<git diff 的范围或提交号>。要做到：<一两句，说清期望行为>。
要打的（≤ 3 条；全打再加对抗清单里相关的几类）：<作者最没把握的地方，写清 文件:行号>
起点：<配方命令；没有就给能直接粘贴的完整命令>
真路径：<看哪个接口 / 哪个页面 / 哪张表 / 哪个文件>
已知、接受的代价（别在这上面花时间，除非你认为比这里说的更严重）：<…>

<贴第 3 节的精简红线>

回报（短，直接作为文字交回）：反例（复现命令、实际、期望、期望从哪来）；没打破的（一行一类）；真路径证据；
清理情况（起的进程、临时目录）；用时。
```

写 spec 的要点：
- **快打不要把背景讲全**：Hacker 自己读 diff。spec 写长了它会照单全打，时间就上去了。
- **点名作者最没把握的地方**，而不是"全面测试一下"。
- **给它对照旧版的办法**（第 4 节"取旧版本对比"）。
- **把已知、接受的代价写进去**，省得它在那上面花时间。

## 7. 回归关卡【项目填写】

- **留下的**：少量快的、守关键不变量的测试。数据不丢（合并 / 导入 / 迁移）、安全边界（路径穿越、跨站、SSRF）、
  配置不丢凭据、资源要关、新页面要有入口。整套几十秒内跑完，提交前必须全绿。
- **删掉的**：只探"改了什么"的测试：断言源码里有某句话的、mock 到看不出行为的、拿当前输出当期望的。删之前确认关键
  不变量都有人守；删掉的留在 git 历史里。
- **以后往里加**：只有 Hack 在这几块打出真 bug 时，才把反例加进来（造数据 + 期望），照现有文件的写法。
  不写"源码里有某句话"的断言，不为关卡另搭测试框架。别处不加测试。

本项目：
- 命令：`npm run typecheck && npm run build`（约 30–60 秒）。用户要求本项目不写测试，所以关卡目前只有类型检查和构建。
- 保留的几块：暂无测试。

## 8. 无损改动走等价性

性能优化、重构、搬代码，"对"的定义是**和旧版逐项一致**：同一份合成数据上，新旧两份代码逐页 / 逐行 / 逐个响应比对
（不只比总数），外加一组前后耗时。Hacker 的任务是找出"不一致"的输入。

## 9. 打出的 bug 要反哺验证工具

Hacker 打出一个配方 / 基准没覆盖到的 bug，说明验证工具缺了那种数据形态（例：数据只放在一个分片里，多分片才出现的 bug
永远测不到）。修 bug 的同时把那种形态加进造数据的工具，**把修复临时改回去，确认工具能报出来**，再改回来。

## 10. 收尾

- 确认 Hacker 起的服务、后台命令都结束了（卡住的命令可能还占着临时目录）；临时目录删干净，尤其是里面有真实数据副本
  或密钥的。
- 关掉它开的窗口；对照旧版本用的副本删掉。
