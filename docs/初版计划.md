### 3.0 window.api（所有阶段共用，阶段 A 一次写全，之后不改形状）

```ts

  | 'SANDBOX_BLOCKED' | 'CANCELLED' | 'INVALID_INPUT' | 'ENCRYPTION_UNAVAILABLE' | 'IO' | 'NOT_IMPLEMENTED'
  | 'HOTKEY_INVALID' | 'HOTKEY_TAKEN';
type Result<T> = { ok: true; data: T } | { ok: false; error: { code: ErrorCode; message: string } };

type PublicSettings = {
  ai: { baseUrl: string; model: string; hasApiKey: boolean };
  autoSummary: { enabled: boolean; time: string };   // 'HH:mm'
  openAtLogin: boolean;
  encryptionAvailable: boolean;
  voiceHotkey: {

type SettingsPatch = {

type ParsedItem = { title: string; date: string | null; time: string | null };
type SummaryResult = {
  headline: string; overview: string;
  order: { id: string; reason: string }[];
  generatedAt: string;          // ISO
  basedOnCount: number;
  tasksFingerprint: string;     // shared/fingerprint.ts 算的，渲染进程拿来判断是否过期
};

interface QingxinApi {
  tasks: {
    // corruptBackup：本次启动备份出的坏文件名；skipped：本次启动跳过的不合法任务条数（见 3.3）

  settings: {

  ai: {

    // draft 不传 = 用已保存的配置；draft.apiKey 不传 = 用已保存的 Key
```

- 主进程对每个 handler 的参数做运行时校验（类型、长度、格式），不合法返回 `INVALID_INPUT`。
- `tasks.save` 校验通过后**立即**更新主进程内存里的任务（再排队写盘），这样紧接着的 `ai.summarize` 用的是最新数据。
- `fingerprint.ts`：对每条任务取 `[id, title, done, dueDate, dueTime]`，按 id 排序后序列化，做 FNV-1a 哈希，输出十六进制字符串。

### 3.2 挡板（sandbox.ts）
环境变量 `QINGXIN_SANDBOX=1` 时：
- 必须同时给 `QINGXIN_DATA_DIR`（绝对路径），在 `app.whenReady` 之前 `app.setPath('userData', 它)`；没给就直接退出并打印原因。
- 开机启动只写进 settings，不调 `app.setLoginItemSettings`。
- AI 地址只允许 `127.0.0.1` / `localhost` / `[::1]`，其它地址返回错误码 `SANDBOX_BLOCKED`。
- 不弹系统通知（改成往渲染进程发事件即可）。
- 另加 `QINGXIN_SANDBOX_QUIET=1`（只在挡板模式下生效）：窗口放到所有屏幕之外、不抢焦点、不进任务栏，照常绘制，
  供自动化验收反复启动时使用，不打扰正在用电脑的人。
它不防故意绕过（例如直接改代码），只防程序自己走到真实数据、真实网络和注册表。

### 3.3 数据
`userData/tasks.json`：`{ "version": 1, "tasks": Task[] }`

```ts
type Task = {
  id: string;               // crypto.randomUUID()
  title: string;            // trim 后 1–200 个字符
  done: boolean;
  dueDate: string | null;   // 本地日期 'YYYY-MM-DD'，null = 没定日期（算今天）
  dueTime: string | null;   // 'HH:mm'，只有 dueDate 不为 null 时才可能有
  createdAt: string;        // ISO
  completedAt: string | null;
  source: 'manual' | 'ai';
};
```

- 渲染进程持有状态，每次改动调用 `tasks.save(全部任务)`；主进程校验每一条（不合法的整批拒绝，返回错误），
  串行写入（只保留最新一份待写），原子写：写 `tasks.json.tmp` → rename 覆盖（Windows 上 EPERM/EBUSY 重试 3 次，间隔 100ms）。
  退出前把待写的刷完。
- 启动读取：文件不存在 = 空列表。
  - 整个文件读不懂（坏 JSON、不是对象、版本不对、tasks 不是数组）→ 把原文件改名为 `tasks.corrupt-<时间戳>.json`，用空列表启动，
    提示「数据文件损坏，已备份为 …」。
  - 文件读得懂、但其中有些任务不合法或 id 重复 → **只跳过这些条**（重复 id 保留第一条），其余照常显示；先把原文件**复制**为
    `tasks.corrupt-<时间戳>.json`，再写回清理后的列表；提示「有 N 条待办数据无法读取，已跳过；原文件备份为 …」。
  - 绝不覆盖、不删除损坏的原文件。提示在本次运行内每次 `tasks.load` 都返回（主进程自己启动时读文件不能把它消费掉）。
  - `tasks.load` 的返回在 3.0 的基础上加一个字段：`skipped: number`（本次启动跳过的条数，整个文件损坏时为 0）。
- 主进程内存里留一份最新任务，供每晚自动总结用。

`userData/settings.json`：`{ version: 1, ai: { baseUrl, model, apiKeyEnc }, autoSummary: { enabled, time: 'HH:mm' }, openAtLogin, windowBounds, lastAutoSummaryDate }`
- API Key 用 `safeStorage.encryptString` 加密后 base64 存；`isEncryptionAvailable()` 为 false 时拒绝保存并提示，**绝不明文落盘**。
- 渲染进程永远拿不到 Key，只拿到 `hasApiKey: boolean`。日志和错误信息里不得出现 Key。
- 默认值：baseUrl ''、model ''、autoSummary { enabled: true, time: '21:00' }、openAtLogin false、voiceHotkey 'Control+Shift+Space'。
  文件里的 voiceHotkey 不合法时按默认值处理。
- 写法同 tasks.json（原子写、坏文件备份后用默认值）。

### 3.4 AI（OpenAI 兼容）
- 跳转：用 `redirect: 'error'`。Electron 44 的 net.fetch 遇到 3xx 会直接抛错（实测：manual 模式 "Redirect was cancelled"，
  error 模式 "Attempted to redirect, but redirect policy was 'error'"，跳转目标收不到任何请求），catch 里按这条错误识别出跳转，
  返回 BAD_RESPONSE「AI 服务地址发生了跳转，请填写最终地址」，不能当成 NETWORK。
- 请求：`POST {baseUrl}/chat/completions`。baseUrl 先 trim、去掉结尾 `/`；如果用户填的以 `/chat/completions` 结尾，去掉这一段。
  只允许 http / https。Header：`Authorization: Bearer <key>`、`Content-Type: application/json`。
  Body：`{ model, messages, temperature: 0.2 }`。不发 `response_format`（很多兼容服务不支持），靠提示词要求只输出 JSON。
- 超时 30 秒（测试连接 15 秒），AbortController；渲染进程可以按 requestId 取消。同一类请求（整理 / 总结）新请求发出时取消旧的。
- 解析回复：取 `choices[0].message.content`，去掉 ```json 围栏，取第一个完整的 `{…}`，JSON.parse，再逐字段校验。
- 错误码 → 中文提示：`NOT_CONFIGURED`（还没配置 AI 服务）、`NETWORK`（连不上 AI 服务）、`TIMEOUT`（AI 响应超时）、
  `AUTH`（401/403：API Key 不对或没有权限）、`RATE_LIMIT`（429：请求太频繁，稍后再试）、`SERVER`（5xx）、
  `BAD_RESPONSE`（AI 返回的内容看不懂）、`SANDBOX_BLOCKED`、`CANCELLED`。
- 整理（parse）：输入用户的一段话（trim 后 1–500 字）。提示词里给：当前本地时间 `YYYY-MM-DD HH:mm 周X`，以及未来 7 天的
  「日期 = 周几」对照表。要求只输出 `{"items":[{"title":"…","date":"YYYY-MM-DD 或 null","time":"HH:mm 或 null"}]}`；
  标题简短（≤ 30 字）、不含时间词；没有可做的事就返回空数组。
  校验：title trim 后为空的丢掉，超 200 截断；date 不是真实日历日期就置 null；time 不合法置 null；date 为 null 时 time 也置 null；
  最多保留 20 条。
- 总结（summary）：主进程拿当前任务（今天列表的未完成 / 已完成、之后 7 天内的未完成），发给 AI，要求只输出
  `{"headline":"≤ 40 字","overview":"≤ 200 字","order":[{"id":"任务 id","reason":"≤ 30 字"}]}`。
  校验：headline / overview 截断；order 里不存在或不属于「今天未完成」的 id 丢掉、重复的去重；今天未完成里没被提到的，按第 4 节的排序
  补在最后、reason 为空。结果带 `generatedAt` 和 `basedOnCount`。
- 测试连接：发一条极短的消息，拿到 200 就算成功。

### 3.7 语音快捷键（src/shared/accelerator.ts + src/main/hotkey.ts）
- 存 settings 的 `voiceHotkey`（Electron accelerator 字符串）。默认 `Control+Shift+Space`。
  **不要用 Ctrl+Space 当默认**：中文 Windows 上它是切换输入法。
- `accelerator.ts`（纯函数，主进程和渲染进程共用）：
  - 规范写法：修饰键按 `Control`、`Alt`、`Shift`、`Super` 的顺序，用 `+` 连接，最后一个是主键。
  - 主键只允许：`A`–`Z`、`0`–`9`、`F1`–`F24`、`Space`。
  - 必须有修饰键；只有 F1–F24 可以单独使用。主键是字母 / 数字 / Space 时，修饰键里必须有 Control、Alt 或 Super
    （只按 Shift + 字母等于打字，不允许）。
  - 禁用：`Alt+F4`、`Control+Space`（提示「这是切换输入法的键」）、`Shift+Space`（全角 / 半角）、`Super+L`、`Control+Alt+Delete`。
  - `fromKeyboardEvent(e)`：把渲染进程的 KeyboardEvent 转成规范写法（用 `e.code` 判断主键，不受输入法和大小写影响；只按了修饰键时返回 null）。
  - `toLabel(acc)`：显示成 `Ctrl + Shift + Space`（Super 显示为 Win）。
  - `validate(acc)`：返回 `{ ok: true } | { ok: false, reason: 中文原因 }`。
- `hotkey.ts`：启动时、设置变更时注册；先注册新的，成功后再注销旧的；新的注册失败 → 旧的保持不变，返回 `HOTKEY_TAKEN`
  （「这个组合被其它程序占用了，换一个吧」）。启动时注册失败 → status `failed`，settings 里的值不动。
  按下时：窗口最小化则还原，显示并聚焦，然后发 `voice:hotkey` 事件。`will-quit` 时全部注销。
- 挡板模式下**不调用 globalShortcut**，status 为 `sandbox`，只校验和保存。
- 渲染进程兜底：窗口有焦点时，按下与设置一致的组合也触发同样的动作（全局快捷键注册成功时系统会先吃掉按键，不会触发两次）。
  输入框里正在用输入法组合（`isComposing`）时不触发。

## 4. 日期规则（src/shared/dates.ts，纯函数，主进程的总结和渲染进程的列表都用它）
- 「今天」= 本地日期，每 60 秒、窗口重新获得焦点时重新计算（跨午夜要自动切换）。
- 今天列表：未完成且（dueDate 为 null 或 ≤ 今天）；已完成且（completedAt 是今天 或 dueDate 是今天）。
- 之后列表：未完成且 dueDate > 今天；已完成且 dueDate > 今天、并且不在今天列表里（今天完成的未来任务只出现在今天的「已完成」，不重复出现）。
- 今天列表的未完成排序：逾期的在最前（按日期升序）→ 有时间的按时间升序 → 没时间的 → 同序按 createdAt 升序。
- 之后列表的未完成排序：按日期升序 → 同一天里有时间的按时间升序在前、没时间的在后 → 同序按 createdAt 升序
  （现有 `sortOpenTasks` 只适合今天列表，之后列表要单独的排序函数）。
- 标签：今天列表显示 `10:00`；逾期显示 `10月12日 · 已过期`（蜜桃色）；之后列表显示 `明天 15:00` / `后天` / `10月18日 周日`。
- 进度：今日完成 = 今天列表里已完成数 / 今天列表总数。

## 8. AI 指令（用户追加）

用户要求 AI 不只会新建，还能完成、取消完成、改日期时间、改标题、删除；用户选定：**删除要确认，其它直接执行**。
新建保持原来的确认卡片（列表里没有编辑待办的入口，AI 建错了在卡片里改最方便）。

- **接口**：`ai.parse` 换成 `ai.command({ requestId, text })` → `{ actions: AiAction[]; unmatched: string[] }`。
  `AiAction`：`add`（item）、`complete`、`reopen`、`reschedule`（date / time 不出现 = 不改，null = 清掉）、`rename`、`delete`，id 是真实任务 id。
- **主进程**（`main/ai/command.ts`）：把现有待办编号发给 AI（今天未完成、之后未完成，最多 100 条；再加今天已完成最多 20 条，给「取消完成」用），
  一行一条「编号. 标题（今天 10:00 / 10-16 / 已过期 10-12 / 已完成）」，AI 只回编号，主进程映射回 id。
  校验：编号不在列表里的丢掉；已完成的不能再完成、未完成的不能取消完成；改标题过 truncateTitle、和原标题一样的丢掉；
  reschedule 的日期时间格式不对就当没写，两个都没写就丢掉；同一任务同一操作只留第一次；最多 20 项；`unknown` 的说法最多 5 条、每条 ≤ 30 字。
  提示词沿用第 7 节的提速写法（第一个字就是 {、/no_think），带一个混合指令的例子。
- **渲染进程**（`lib/aiActions.ts`、`state/useAiFlow.ts`）：收到结果后，完成 / 取消完成 / 改时间 / 改标题马上作用在当前列表上，
  提示条「已完成「…」」或「已处理 N 项：完成 1、改时间 1…」带撤销；撤销按字段组（标题、完成状态 + 完成时间、日期 + 时间）
  改回去：这次动过、且整组之后没被别处改过的才改回，不会只改回一半。从提示条撤销过以后，卡片上不再提这部分。
  有新建或删除时显示确认卡片（新建可改，删除默认勾选、点「执行 N 项」才删），卡片上写明已直接处理了什么、哪些没找到。
  执行后一句话就是一次撤销：撤销会连同直接处理的改动一起撤回。关掉卡片时再给一次直接处理部分的撤销提示。
  要删的已经被别处删掉、也没有新建时，点执行什么都不做。待办标题在提示词里加引号，标题里写的「2. …」不会被当成另一条。
  只有没对上的说法时显示「没对上现有的待办」卡片；什么都没识别出来时沿用「这句话里没找到要做的事」。
- 输入区模式改名「AI 指令」，提示文字「Enter 交给 AI：新建、完成、改时间、删除都行 · Ctrl+Enter 直接添加」。


## 9. Gemini 原生接口与语音输入（用户追加）

用户的 AI 服务是 Sub2API 反代的 Google Antigravity 账号（Gemini 3.8 Flash）。Sub2API 的 OpenAI 兼容入口
`/v1/chat/completions` 只转文字、图片和文件，音频会被丢掉；Gemini 原生入口
`/antigravity/v1beta/models/<模型>:generateContent` 原样转发 `contents`，用户在自己机器上实测语音能被听写。

- **接口格式**（`main/ai/providers.ts`）：设置里的 AI 服务多一个 `apiFormat`：`openai`（默认，原来的行为）或 `gemini`。
  Gemini 原生：`POST {baseUrl}/v1beta/models/<模型>:generateContent`，baseUrl 去掉用户一起粘贴进来的 `/v1beta`、`/v1beta/models/…`；
  Key 放 `x-goog-api-key`；system 提示词放 `systemInstruction`，用户消息放 `contents[0].parts`；
  `generationConfig: { temperature: 0.2, thinkingConfig: { thinkingLevel: 'low' } }`（Sub2API 据此选 `-low` 变体，不写默认是 high，慢得多）。
  回复取 `candidates[0].content.parts` 里的文字，跳过 `thought: true` 的思考部分；被拦截（`promptFeedback.blockReason`）提示「AI 拒绝处理这次的内容」。
  测试连接沿用已存 Key 的同站点规则不变（站点按各自格式剥离后缀后的地址算）。
- **语音输入**：点输入框左边的麦克风或按语音快捷键开始录音，再按一次 / 点「说完了」结束，Esc 或「取消」放弃，最长 60 秒自动结束，
  短于 0.6 秒提示「太短了」。录音（`lib/recorder.ts`）：`getUserMedia` 单声道 → MediaRecorder（webm/opus）→ 解码 →
  `OfflineAudioContext` 重采样成 16 kHz 单声道 → 16 位 PCM WAV（`lib/wav.ts`）→ base64。录音卡片（`VoiceCard`）显示计时和音量条。
  录音中打开设置就放弃这次录音；结束、取消、出错、关窗口都会关掉麦克风。
- **语音指令**：`ai.command({ requestId, audio: { mimeType: 'audio/wav', data, seconds } })`（和 `text` 二选一；
  base64 ≤ 4 MB、时长 ≤ 90 秒）。提示词多一句「用户的话是附带的一段中文语音：先把听到的原话写进 heard」，格式改成
  `{"heard":"…","actions":[…]}`，WAV 作为 `inlineData` 跟在用户消息后面；请求超时 60 秒。返回多一个 `heard`（压成一行、≤ 500 字，空的为 null）。
  渲染进程把 heard 当作「原话」：确认卡片默认展开它；「重新输入」把它放回输入框；没识别出操作时可「直接存为待办」。
  没听清（heard 为空且没有操作）时提示「没听清你说的话」，可以「再说一次」。出错时「重试」重发同一段录音。
  语音指令不会清掉输入框里已经打了一半的字。
- **只有 Gemini 原生能用语音**：没配置 AI、或接口格式是 OpenAI 兼容时，点麦克风提示去设置；主进程也拒绝把录音发给 OpenAI 兼容接口。
- **权限**（`main/permissions.ts`）：网页权限默认全给，改成只给自己的页面两项：麦克风（只要声音，要摄像头一律拒绝）和剪贴板写入（复制总结）。
- 悬浮窗没有语音。设置里快捷键下方的灰字改成「语音输入要求 AI 服务的接口格式是 Gemini 原生…」。

## 10. 第三版（用户追加）

用户追加：偶发「AI 返回的内容看不懂」；鼠标侧键设不了语音键；界面分区更合理；悬浮窗透明度；AI 要有助理的感觉。
用户选定：三栏布局；助理「像人一样回一句话」（不做问答、多轮对话、自动朗读）；侧键不拦原功能。

- **偶发解析失败**：Gemini 请求加 `responseMimeType: 'application/json'`（JSON 模式；Sub2API 原样转发 generationConfig，
  且会在系统提示词前插一段「你是 Antigravity 编程助手」，可能把模型带偏成写解释文字）；字符串里直接写了换行等控制字符时转义后再解析；
  指令只接受带 `actions` 数组的对象（外层写坏时不再把第一条 `{"op":…}` 当成整个回复）；
  出错原因写清楚（没有正文时带 finishReason、被截断、不是完整 JSON、没有操作列表），出错卡片上能看到。
- **助理回复**：指令格式加 `"reply"`（≤ 60 字，口语，说清做了什么、提醒冲突 / 过期 / 扎堆、可给小建议；新建和删除说成「帮你列好了」「确认一下就删」）。
  `AiCommandResult.reply`（去掉看不见的字符、≤ 120 字，空的为 null）。渲染进程把「原话 + 回复」记进右栏对话（只在内存，最多 30 条，不发给 AI）；
  AI 没写回复时用直接执行的说明顶上。
- **三栏布局**（`AppShell`、`NavPanel`、`AssistantPanel`）：左栏 200px（今天 / 之后、今日进度、悬浮窗开关），中间列表，右栏 400px AI 助理
  （「对话 / 今日总结」两页，底部是提示条、AI / 录音卡片或输入框）。今日总结从抽屉挪进右栏。< 1000px 收起左栏、列表上方恢复标签页和进度；
  < 760px 右栏挪到列表下面占约一半高度。设置里「恢复默认」挪到「修改」旁边，不再单独占一行。新装默认窗口 1240×780。
- **悬浮窗不透明度**：`floatWindow.opacity`（0.3–1，默认 1），设置「窗口」里滑块调，停 200 毫秒再保存，`setOpacity` 实时生效。
- **鼠标侧键**：语音键可以是 `Mouse4`（后退键）/ `Mouse5`（前进键），单独使用。主进程用 `uiohook-napi`（系统级输入钩子，用到时才加载，
  加载失败只是侧键用不了）全局监听，只听不拦；300 毫秒内的重复按下当一次。设置里录制时按一下侧键即可。
  打包：`uiohook-napi` 是唯一的运行时依赖（React、字体改为开发依赖，由 Vite 打进页面），安装包带上它的预编译 win32-x64 二进制，`npmRebuild: false`。
